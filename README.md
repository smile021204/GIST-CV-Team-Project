# Sequential Inference + PDF Visualization

This branch adds:

- **`CustomDjiDataModule`** — minimal DataModule for the GIST drone dataset
  (poses.txt + intrinsics.json + tiles.pkl + flat images/ directory).
- **`scripts/visualize_sequential.py`** — per-frame PDF visualization of
  single-shot vs sequential inference for any checkpoint.
- **`scripts/evaluate_sequential.py`** — numerical sequential evaluation
  (Recall@1/3/5 m, median errors).
- One-line patches to **`maploc/data/__init__.py`** (registers the DataModule)
  and **`maploc/evaluation/viz.py`** (fills in the stub
  `plot_example_sequential`).

The PDFs `mgl_fixed_256.pdf` and `finetune_fixed_256.pdf` in the report are
generated by this script.

## Expected Dataset Layout

```text
datasets/gist_abc/
├── images/                          ← flat directory of DJI .JPG files
├── poses.txt                        ← <filename> <lat> <lon> <alt> <roll> <pitch> <yaw>
├── intrinsics.json                  ← PINHOLE intrinsics (fx, fy, cx, cy, width, height)
├── tiles.pkl                        ← built with scripts/build_tiles.py
├── splits_balanced.json             ← DEFAULT split file (train/val/test lists of filenames)
└── splits_test.json                 ← optional alternate split (used via --splits_filename)
```

The DataModule reads:
- `poses.txt` for GT lat/lon and roll/pitch/yaw per frame
- `intrinsics.json` for the shared camera intrinsics
- `tiles.pkl` for OSM tiles
- `splits_balanced.json` (default) or any other `splits_*.json` file you pass

## 1. Sequential Visualization — generate the PDFs

The same command works for any checkpoint; only `--experiment` changes.

### a) Run with the original OrienterNet MGL checkpoint

```bash
python -m scripts.visualize_sequential \
  --experiment OrienterNet_MGL \
  --split test --stride 1 \
  --crop_size_meters 256 \
  --fixed_search \
  --output outputs/viz_seq/mgl_fixed_256.pdf
```

This downloads `orienternet_mgl.ckpt` on first use (~700 MB) and caches it in
`experiments/`. Per-frame PDF pages are written to the output path. With
`--fixed_search`, the model uses ONE search canvas centered on the trajectory
centroid for every frame (matches the campus-buildings experiment in the
report).

### b) Run with your fine-tuned checkpoint

Same command, pointing `--experiment` at a checkpoint file path:

```bash
python -m scripts.visualize_sequential \
  --experiment datasets/gist_abc/checkpoints/finetune_v1.ckpt \
  --split test --stride 1 \
  --crop_size_meters 256 \
  --fixed_search \
  --output outputs/viz_seq/finetune_fixed_256.pdf
```

Any `.ckpt` produced by `maploc.train` is accepted (model architecture is read
from the checkpoint's `hyper_parameters`).

### c) Use a different split file to view only specific frames

`--splits_filename` accepts any JSON in `datasets/gist_abc/` with the same
`{"train": [...], "val": [...], "test": [...]}` structure. Useful for
focusing on a curated subset of test images:

```bash
python -m scripts.visualize_sequential \
  --experiment OrienterNet_MGL \
  --split test --stride 1 \
  --crop_size_meters 256 --fixed_search \
  --splits_filename splits_test.json \
  --output outputs/viz_seq/mgl_subset.pdf
```

To make your own subset, copy `splits_balanced.json` and trim the `test` list:

```python
import json
s = json.load(open('datasets/gist_abc/splits_balanced.json'))
s['test'] = ['DJI_xxxx_V.JPG', 'DJI_yyyy_V.JPG']      # only the frames you want
json.dump(s, open('datasets/gist_abc/splits_subset.json', 'w'), indent=2)
```

Then pass `--splits_filename splits_subset.json`.

## 2. What's in each PDF page

The header page shows the full trajectory + the fixed search canvas. Every
frame page has a 3×3 layout:

| Row | Left | Middle | Right |
|---|---|---|---|
| 1 | input image | OSM map + GT (black) / single-pred (green) / seq-pred (red) trajectories + current poses | per-frame metrics text box |
| 2 | BEV feature (PCA→RGB) | map feature (PCA→RGB) | feature panel explanation |
| 3 | single-frame log P(pose) heatmap | sequential log P(pose) heatmap | log-likelihood legend |

Black star = GT pose, green dot = single-frame argmax, red dot = sequential
argmax. Top-20 pose candidates (local maxima of the posterior) are overlaid
as small white arrows on the log-P panels.

## 3. Important script flags

| Flag | Default | Effect |
|---|---|---|
| `--experiment` | required | Pretrained name (`OrienterNet_MGL`) or path to `.ckpt`. |
| `--split` | `test` | `train` / `val` / `test`. |
| `--stride` | `5` | Render every Nth frame. Inference still runs on every frame. Use `1` for full sequence. |
| `--crop_size_meters` | `96` | Per-frame search canvas half-width (meters). `128` covers most of the campus; `256` for the broad campus-buildings test. Bigger = more GPU memory. |
| `--fixed_search` | off | All frames share a SINGLE search canvas centered on the trajectory centroid (instead of one canvas per frame). This is the campus-buildings test setting. |
| `--no_yaw_prior` | off | Drop the GT-yaw prior (±10°) and let the model search the full 360°. Harder localization. |
| `--max_init_error_rotation` | `10` | Yaw-prior half-width in degrees. Set higher to relax. |
| `--add_map_mask` | off | Re-enable the map-mask (KITTI default). Off in this branch so the search is unconstrained inside the canvas. |
| `--splits_filename` | `splits_balanced.json` | Which split JSON in `datasets/gist_abc/` to read. |
| `--num_rotations` | `64` | Rotation grid resolution. Bump to 128/256 for sharper yaw if your GPU allows. |
| `--output` | required | Path to output PDF. |

## 4. Numerical sequential evaluation (optional)

For the official Recall@1/3/5 m and median errors instead of the per-frame
visualization:

```bash
python -m scripts.evaluate_sequential \
  --experiment OrienterNet_MGL \
  --split test --sequential \
  --output_dir outputs/eval/mgl_seq

python -m scripts.evaluate_sequential \
  --experiment datasets/gist_abc/checkpoints/finetune_v1.ckpt \
  --split test --sequential \
  --output_dir outputs/eval/finetune_seq
```

Uses the same `CustomDjiDataModule`. `--sequential` enables the
`RigidAligner`-based eval (matches upstream `maploc.evaluation.run`).

## 5. Run-time and memory expectations

At `--crop_size_meters 256 --fixed_search --stride 1 --num_rotations 64`:

- Inference: ~3 s/frame on RTX 4090 → ~5 min for 97 test frames
- GPU peak: ~10 GB
- Output PDF: ~80 MB (98 pages, one header + 97 frame pages)

Drop `--num_rotations` to `32` or `--crop_size_meters` to `128` if you OOM.
